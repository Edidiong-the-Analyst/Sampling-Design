# Sampling Design & Difference-in-Differences Evaluation of a Community Contraceptive Counselling Programme

**A portfolio demonstration project in R (base R only, no external packages required).**

> **All data in this project is synthetically generated.** It does not
> come from any real organisation, programme, or survey. The scenario
> (a community-based contraceptive counselling programme evaluated across
> six Nigerian states) is a realistic but entirely simulated setup, built
> to demonstrate an evaluation design + causal analysis workflow relevant
> to reproductive health / development programme evaluation.

## What this demonstrates

- Designing a **sampling strategy** for an impact evaluation: minimum-detectable-effect-driven sample size calculation, design-effect adjustment for cluster intra-correlation, and proportional stratified allocation across strata (states).
- Simulating a **cluster-level panel dataset** across three survey waves (two pre-programme, one post-launch).
- Estimating a **Difference-in-Differences (DiD)** model of programme impact on modern contraceptive prevalence (mCPR).
- Computing **cluster-robust standard errors from scratch** (a CR1 sandwich estimator implemented in base R — no `sandwich`/`fixest`/`lfe` package required).
- Testing the **parallel-trends assumption** using the pre-programme waves, rather than just assuming it holds.
- Running a **permutation (randomization-inference) placebo test** as a second, assumption-light robustness check on the main result.

## Why this design

Real programme evaluations rarely get a second chance at data collection, so the sampling strategy has to be defensible before fieldwork starts, and the analysis has to interrogate its own assumptions rather than just report a p-value. This project is built to mirror that discipline: `02_sampling_design.R` produces the sample size and allocation *before* any outcome data exists, and `03_did_analysis.R` doesn't stop at the headline DiD estimate — it checks pre-trends and stress-tests the result with a placebo test, in the spirit of "test robustness and challenge your own findings" rather than taking one regression at face value.

## How to run

Requires only base R (tested on R 4.3, no packages installed beyond base):

```bash
cd scripts
Rscript 01_generate_synthetic_data.R
Rscript 02_sampling_design.R
Rscript 03_did_analysis.R
```

## Key results (this run)

- **Sampling design:** to detect an 8-percentage-point change in mCPR from a 25% baseline, at 80% power / 5% significance, accounting for clustering (ICC = 0.02, ~180 respondents/cluster), the design requires **26 clusters (13 per arm)**, allocated proportionally across the six states.
- **True simulated effect:** +8.0 percentage points (built into the data-generating process).
- **DiD estimate recovered:** **+5.79 percentage points** (cluster-robust SE = 0.76, p < 0.001) — the estimate is attenuated relative to the true effect because the simulation also lets a "remoteness" covariate suppress post-period gains, which is deliberate: real effects rarely come back exactly as simulated, and the analysis should say so rather than overstate precision.
- **Pre-trend check:** p = 0.36 on the treated × pre-period interaction — no evidence that treated and control clusters were already diverging before the programme launched, which supports (but does not prove) the parallel-trends assumption the DiD relies on.
- **Placebo test:** the real effect falls far outside the distribution of 1,000 placebo (randomly reassigned) effects (permutation p < 0.001), reinforcing that the result is not an artefact of the specific treatment/control split.

## Notes on scope and limitations

This is a demonstration of method, not a claim of a real evaluated result. In a live evaluation, the ICC and baseline mCPR used for the power calculation would come from formative research or prior survey rounds, cluster boundaries would come from an actual sampling frame (e.g. enumeration areas), and ethics/consent processes would govern data collection. The DiD specification here is intentionally simple (no covariate adjustment beyond weighting by cluster survey size); a real analysis would also consider covariate-adjusted DiD, an event-study specification with more pre-periods if available, and sensitivity to the clustering assumption itself.
